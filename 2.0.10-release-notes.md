# Apocapocket 2.0.10

Weapon recovery can now run after a puff while a joint is still lit. Version 2.0.9 protected the entire burn phase, which
skipped recovery in the reported case. The guard now distinguishes the lighting animation from ongoing smoking: both
smoking arms must already be hidden, the lighting FSM must be idle and burn progress must be valid before recovery is allowed.

Lighting and unfinished/unknown animation states stay protected. Native smoking continues to own burn progress, held Smoke
input, lights, consumption, discarded items and weed effects. Recovery does not replay End or reset the joint.
Extra-slot weapons and parked native hosts are preserved through the existing inventory transaction.

The watchdog also covers a selected weapon whose native hand handler remains inactive despite visible weapon prompts, and
honours the native re-equip delay when game time is slowed.

Recovery and state-snapshot messages require Debug/VerboseLog = true. Default logging stays quiet. If the issue persists,
enable that setting, restart and reproduce the puff/weapon draw, then remain in gameplay for at least 15 seconds and copy
BepInEx/LogOutput.log. Snapshots identify animation, hand, pause, menu, vehicle, save and transaction guards without clearing
another mod's pause or moving another mod's held object.

Replace the previous DLL with the included BepInEx/plugins/Apocapocket/Apocapocket.dll and restart. Keep only one plugin DLL.
Existing configuration, bindings and save format are retained.

Verified with 173 production-code checks and native Mono/Harmony checks. The affected player's reproduction still needs
validation; their prior log confirmed 2.0.9 loaded but did not capture the stalled weapon states.
